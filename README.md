# metabolomics-dashboard-demo

Turns an omics analysis into one HTML file that anyone can open, with no
server, notebook or network connection.

`omicsdash` simulates a metabolomics study, runs a short association pipeline
on it and renders a single dashboard: curation counts, QC drift, PCA, and a
volcano plot and effect estimates for each outcome. A filter bar searches,
sorts and subsets the result tables in the browser. It's a demo of the
reporting approach, not an analysis of a real cohort.

[View the example dashboard](https://wrlog.github.io/metabolomics-dashboard-demo/)

```bash
pip install git+https://github.com/Wrlog/metabolomics-dashboard-demo
omicsdash --out dashboard.html
```

## Data

All of it is synthetic, generated by `omicsdash.simulate` from a seed. There's
no real study, subject, sample or measurement in the repo, and `git clone` plus
`omicsdash` is the whole setup. The simulator plants a known set of
feature–outcome associations and lists them in an appendix, so you can check
the output against the ground truth.

## Why one HTML file

Results often go to people who won't run your code, like a clinician, a
project lead or a reviewer. A notebook needs a kernel, a Shiny or Streamlit app
needs a server someone keeps running, and a PDF can't be scrolled at full
figure resolution.

Here the figures are base64 PNGs and the CSS and script are inline, so the
file can be emailed, attached to a ticket, committed next to the code that made
it, or opened years later with nothing installed. The tests enforce this: no
external URL, `<script src>` or `<link href>` in the output, so opening it
fetches nothing.

## Controls

These all run client-side:

| Control | What it does |
| --- | --- |
| **Outcome** | Shows one outcome's section, or all of them |
| **Search** | Filters rows by feature ID or m/z as you type |
| **Annotation** | Restricts rows to one MSI annotation level |
| **Sort by** | Re-orders every table by p-value, effect size, m/z, retention time or annotation level |
| **Significant only** | Keeps just the FDR hits |
| **Reset** | Returns every control to its default |
| **Dark mode** | Switches theme, overriding the OS preference either way |

Each table has every curated feature, not just the top N, so search can find
anything. A line under each heading shows how many rows are visible. The
figures are static images, so the outcome selector hides whole sections
instead of redrawing them.

Nothing is hidden on load, so with JavaScript off the page still reads fine;
only the controls stop working. Printing shows all rows and sections again.

## Pipeline

| Step | What happens |
| --- | --- |
| **Curation** | Drop features detected in under 70% of samples; drop features with pooled-QC RSD above 30%; impute remaining gaps at half the feature minimum; log2-transform; median-centre each sample |
| **PCA** | SVD on the centred table, reported with variance explained and coloured by acquisition batch, as an unsupervised check on whether batch dominates biology |
| **Associations** | One OLS model per feature per outcome (`feature ~ outcome + age + sex + bmi`), fitted as a single batched least-squares solve, with Benjamini–Hochberg control across features |

Estimates are log2 abundance change per standard deviation of the outcome, so
outcomes on different scales can be compared. The three simulated outcomes
are wearable-style readouts (daily step count, sleep efficiency, resting heart
rate), since pairing untargeted metabolomics with continuous phenotype data is
a common study design.

## Usage

```bash
omicsdash --out dashboard.html          # defaults: 60 subjects, 400 features
omicsdash --subjects 120 --features 800 --planted 20 --seed 42
omicsdash --alpha 0.10                  # looser FDR threshold
```

Or from Python, if you want the intermediate objects:

```python
from omicsdash import simulate_study, run_all, build_report

study = simulate_study(n_subjects=80, n_features=500, seed=42)
curated, components, results = run_all(study)

results["sleep_efficiency"].head()      # a tidy per-feature result table
build_report(study, curated, components, results, "dashboard.html")
```

## Notes

Colours come from a palette validated for colour-vision deficiency, and
categorical series only use its three scatter-safe colours. Volcano and forest
plots show direction with a diverging blue/red pair, grey for "no call". No
rainbow, and colour is never the only cue: every figure has a legend and a
table with the same numbers.

For dark mode each figure is rendered twice, with marks picked for a light and
a dark background, and CSS shows the right one rather than inverting the image.
It follows the OS setting and respects an explicit `data-theme`.

The analysis uses numpy, pandas, scipy and matplotlib. The browser side is
about 80 lines of plain JavaScript inlined into the page, with no plotting
framework, templating engine, web stack or CDN.

## Development

```bash
pip install -e ".[dev]"
pytest
ruff check .
```

The tests cover reproducibility from a seed, the curation thresholds, a
hand-checked Benjamini–Hochberg case, recovery of the planted effects with the
right sign, false-positive control, the null case where nothing should be
found, and that the rendered file has no external references. For the
interactive layer they check that every control the script binds to exists,
every row carries the data attributes the filters read, and nothing starts out
hidden.
