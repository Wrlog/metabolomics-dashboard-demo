# metabolomics-dashboard-demo

Turn an omics analysis into a single HTML file that anyone can open — no
server, no notebook, no network.

`omicsdash` simulates a metabolomics study, runs a short association pipeline
over it, and renders the whole thing as one self-contained dashboard: curation
counts, QC drift, PCA, and a volcano plot plus effect estimates for each
outcome. It is a demonstration of the reporting pattern, not an analysis of any
real cohort.

**[View the example dashboard](https://wrlog.github.io/metabolomics-dashboard-demo/)**

```bash
pip install git+https://github.com/Wrlog/metabolomics-dashboard-demo
omicsdash --out dashboard.html
```

## All data here is synthetic

Everything the dashboard reports is generated by `omicsdash.simulate` from a
seed. There is no real study, subject, sample or measurement in this
repository, and none is needed to run it — `git clone` and `omicsdash` is the
whole setup. The simulator plants a known set of feature–outcome associations
and reports them in an appendix, so the output can be checked against ground
truth rather than taken on trust.

That property is also what makes this useful as a demo: the pipeline is
exercised end to end on data whose right answer is known.

## Why a single HTML file

Analysis results usually have to travel to people who will not run your code —
a clinician, a project lead, a reviewer. A notebook needs a kernel, a Shiny or
Streamlit app needs a server that someone has to keep running, and a PDF cannot
be scrolled through at full figure resolution.

A self-contained HTML file has none of those requirements. Figures are embedded
as base64 PNGs and the CSS is inline, so the file can be emailed, attached to a
ticket, committed next to the code that produced it, or opened years later with
nothing installed. The test suite enforces this: the rendered output must
contain no `<script>`, no `<link>`, and no external URLs.

## What the pipeline does

| Step | What happens |
| --- | --- |
| **Curation** | Drop features detected in under 70% of samples; drop features with pooled-QC RSD above 30%; impute remaining gaps at half the feature minimum; log2-transform; median-centre each sample |
| **PCA** | SVD on the centred table, reported with variance explained and coloured by acquisition batch, as an unsupervised check on whether batch dominates biology |
| **Associations** | One OLS model per feature per outcome — `feature ~ outcome + age + sex + bmi` — fitted as a single batched least-squares solve, with Benjamini–Hochberg control across features |

Estimates are reported as log2 abundance change per standard deviation of the
outcome, so they are comparable across outcomes on different scales.

The three simulated outcomes are wearable-style readouts — daily step count,
sleep efficiency and resting heart rate — chosen because pairing untargeted
metabolomics with continuous phenotype data is a common study design.

## Usage

```bash
omicsdash --out dashboard.html          # defaults: 60 subjects, 400 features
omicsdash --subjects 120 --features 800 --planted 20 --seed 42
omicsdash --alpha 0.10                  # looser FDR threshold
```

Or from Python, when you want the intermediate objects:

```python
from omicsdash import simulate_study, run_all, build_report

study = simulate_study(n_subjects=80, n_features=500, seed=42)
curated, components, results = run_all(study)

results["sleep_efficiency"].head()      # a tidy per-feature result table
build_report(study, curated, components, results, "dashboard.html")
```

## Design notes

**Charts.** Colours come from a palette validated for colour-vision
deficiency; only the three-slot subset that is safe for scatter plots is used
for categorical series. Direction in the volcano and forest plots uses a
diverging blue/red pair with grey for "no call" — never a rainbow, and never
colour alone: every figure has a legend, and every figure is backed by a table
of the same numbers.

**Dark mode.** Each figure is rendered twice, once with marks chosen for a
light surface and once for a dark one, and CSS picks. It is not an inverted
image, and it respects both the OS setting and an explicit `data-theme`.

**Dependencies.** numpy, pandas, scipy and matplotlib. Nothing else — no
plotting framework, no templating engine, no web stack.

## Development

```bash
pip install -e ".[dev]"
pytest
ruff check .
```

The tests cover reproducibility from seed, the curation thresholds, a
hand-checked Benjamini–Hochberg case, recovery of the planted effects with the
right sign, false-positive control, the null case where nothing should be
discovered, and the self-containment of the rendered file.
